# PIP-108 [iOS] Grok proposals + Ask + Settings

Ticket: https://linear.app/telco-paytm/issue/PIP-108/grok-proposals-ask-settings

## Delivered

Grok orchestrator with **engine validation before confirm card**, Ask starters, Settings Reset demo seed, and template fallback when Grok is unavailable. Extends tip Ask / Settings / Grok surfaces (PIP-61 / 63 / 65 / 95) without rewriting History / Transfer / Ledger mutation paths.

| Type / file | Role |
|-------------|------|
| `GrokProposalOrchestrator` | Draft → validate (GoalValidation / Standing / Transfer) → confirmable / invalid / unavailable |
| `AskViewModel` / `AskTabView` | Ask starters; submit via orchestrator; Confirm re-validates before sheet |
| `GoalChatViewModel` | Goal proposals validated before proposal card |
| `AskService.askStarters` | Idle chips alias (design frame 19) |
| `SettingsService.welcomeStateAfterDemoReset` | Post–Reset Welcome seed (DemoData accounts) |
| `ContentView.returnToWelcome` | Uses Settings seed after Reset demo |
| `GrokProposalOrchestratorTests` | Fallback + validate + Reset seed coverage |

## Trust boundary

- Grok output is a **draft only**.
- `LedgerEngineCore` / `TransferService` / `StandingSplitService` / `GoalValidationService` validate before a confirm card is shown.
- Orchestrator **never** mutates `PersistedAppState`, moves money, or computes settlement amounts.
- Confirm still opens the existing Transfer / Goal form / Standing split sheets (engine applies mutations there).
